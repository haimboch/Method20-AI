# METHOD 20 | CHART-ONLY MODE (2026-10-30)

**Current active behavior:** Daily email charts for the watchlist only. Each chart has exactly 95 daily Japanese candlesticks, SMA20, daily Volume and CCI(14). There are NO trading signals, candle pattern markings, trigger levels, support/resistance zones, portfolio tables or stop warnings.

The overnight EOD workflow fetches verified Massive daily OHLCV and produces an HTML report and chart images. The morning email workflow sends the same charts inline. Legacy strategies and stored market zone/trade data files are retained as inactive historical code/data; the report engine does not read or update them. The manual trade-manager workflow has been disabled. Previous draft PR #1 has been closed without merging.

The latest report metadata sets `report_type=CHART_ONLY` and `candles_per_chart=95` to prevent reusing obsolete report artifacts when preparing an email.

## הרצה בענן ללא התקנת Python
1. פתח את לשונית Actions במאגר.
2. בחר **METHOD 20 EOD Report**.
3. לחץ **Run workflow** ובחר main.
4. המתן לסיום הריצה; בתחתית עמוד הריצה הורד את ה-Artifact בשם `method20-html-report`.

## סטאפ שנשבר אחרי טריגר
מצב READY הופך ל-TRIGGERED כאשר נר מאוחר יותר חוצה את שיא נר האיתות. מעתה הסטאפ נשאר במעקב גם לאחר הטריגר: אם באחד הנרות הבאים מחיר ה-LOW יורד מתחת ל-LOW המקורי של נר האיתות, מצבו מתעדכן ל-BROKEN ונשמר כאירוע היסטורי עם תאריך השבירה. מצב BROKEN, כמו INVALIDATED או AMBIGUOUS, לא מציג בגרף מסגרת איתות כחולה או קו טריגר, ולא מוצג כרמת כניסה תקפה בגוף המייל. אזורי התמיכה וההתנגדות הטכניים נשארים, מכיוון שאינם סטאפים. נגיעה שווה בדיוק ברמת ה-LOW אינה שבירה, ורק ירידה מתחתיה שוברת. תבניות נרות שוריות בזהב נשארות עצמאיות מהמצב של סטאפ METHOD20.

## סדר הצגת הדוח ופרטי סטאפ

## 30 October 2026: METHOD 20 implementation release

The latest working design is described in [METHOD20_IMPLEMENTATION.md](METHOD20_IMPLEMENTATION.md).

**Manual trade entry:** Go to Actions > **METHOD 20 Manual Trade Manager** > **Run workflow**. Select BUY / SELL_PARTIAL / UPDATE_STOP / CLOSE / SKIP_TRADE and provide the ticker. For BUY, provide quantity, execution price, original stop and signal_date. For SKIP_TRADE, provide the original signal_date. For UPDATE_STOP, provide the newly raised stop. SELL_PARTIAL uses shares and executed price; CLOSE uses executed price and sells the entire remaining tracked quantity. Actions does not place broker orders.

**Verification:** The **METHOD 20 Validation** workflow compiles Python and runs the unit tests. Verify it is green before relying on the scheduled EOD and email workflows. Then use a small manual test transaction and inspect the following morning email. Keep the repository private because the ledger records trading positions.
